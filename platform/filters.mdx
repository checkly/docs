On Monitors, Heartbeats, Test sessions, Error Groups and Reporting, you filter the list in the filter field above it. Each filter is a block with a field, an operator and a value, such as **status is failing**. Filters join with **and** or **or**. Groups let you mix both.

## Add a filter

Click the filter field to list every field you can filter on. Each field shows a short description. Pick a field, or type the start of its name and press Enter. Typing the name followed by a colon, such as `name:`, does the same.

A text field such as **Name** then waits for its value. Type it and press Enter.

A field with a fixed set of values, such as **Status** or **Tags**, starts with one of its values. Click the value to pick others. With the keyboard, move to the value and start typing.

Fields like **Tags** take several values. The filter then matches any of them. The block shows how many it holds, such as **3 tags**. Long lists, such as your tags, have a search at the top of the picker.

Text that doesn't start a field name searches by name when you press Enter. On Test sessions, it searches the project name. On Error Groups, it searches the error message.

## Fields

| Screen | Fields |
|--------|--------|
| Monitors | Name, Group, URL, Logical ID, Status, Check type, Tags, Project and Traces |
| Heartbeats | Name, Ping URL, Status, Tags, Period, Grace and Availability |
| Test sessions | Project, Environment, Branch, Commit, User, Has user, Status, Provider, Duration, Check, Check type, Tags and File |
| Error Groups | Message, Project, Environment, Check type, Playwright project and Count |
| Reporting | Name, Group, URL, Logical ID, Status, Ran, Check type, Tags, Project, Location, Created by, Success, Avg, P95 and P99 |

- **Text fields** such as **Name**, **Group** and **URL** match when the text holds every word you type. The words can be in any order.
- On Monitors and Reporting, **Tags** matches the tags of a check and the tags of its group.
- On Reporting, **Status** is the alert state during the time range. **Failing** matches a check that was failing at some point in the range. A failure that started before the range and was still open counts. **Degraded** works the same way. **Passing** matches a check that ran in the range and was never failing or degraded. A check changes state only when it raises an alert. A failed run that raised no alert doesn't make it failing.
- On Reporting, **Created by** matches the user or the API key that created the check.
- On Reporting, **Ran** is true for a check with results in the time range, and false for one without.
- On Reporting, **Location** matches a check that runs in one of the locations. When you [group by location](#group-the-rows), it matches the rows of those locations.
- On Reporting, **Success**, **Avg**, **P95** and **P99** compare the numbers the table shows for the time range. **Success** is a percentage, such as `99.9`. **Avg**, **P95** and **P99** are response times, such as `500ms` or `2s`. A number without a unit is in milliseconds. **Avg**, **P95** and **P99** count only runs with a measured response time. A failed run that records no response time doesn't count. A check without results in the time range matches none of the four. A check whose runs all failed shows a dash for **Avg**, **P95** and **P99**. It matches none of them. When you group by location, a check matches on its numbers across all locations.
- **Project** shows when the account has checks deployed with the [Checkly CLI](/cli/overview). **Traces** shows when the account [imports traces](/resolve/traces/import/overview).
- **Period**, **Grace** and **Duration** compare durations such as `30s`, `5m`, `1h` or `1d`. **Availability** compares the percentage for the selected time range. These fields and the Reporting numbers take `>`, `>=`, `<`, `<=` and `=`.
- On Test sessions, **Commit** matches the commit ID or its message. **User** matches the person or the API key that started the session. **Has user** is false when no person or API key is linked to the session. **Duration** is how long the session ran. A session still running never matches it.
- On Test sessions, **Check**, **Check type**, **Tags** and **File** match a session when any check that ran in it matches. **Tags** matches the tags of the check and of its group. **File** is the Playwright test file.
- On Error Groups, **Count** compares the number of errors in the time range. The time range filters error groups by when they were last seen.
- The **Test Sessions** and **Error Groups** tabs each have their own filters. Switching tabs clears them.

## Pick the time range

The date picker left of the filter field sets the time range. Click it and pick a preset, such as **Last 24 hours**. To pick days on a calendar, open **Custom**. Set the start and end times, then click **Apply**. A custom range shows as its days, such as **21-22 Oct**. The time range always applies on top of the filters. A view saves it with the filters.

## Join filters

Filters join with **and** by default. The list then shows what matches every filter. Click the word between two filters to switch it to **or**. The list then shows what matches any filter. The switch applies to every join at that level.

To join only the next filter with **or**, type `or` and a space. The **or** shows at the end of the field. The next filter you add joins with it. For example, with **status is failing and name contains api** in the field, type `or url` and press Enter. Then type `health` and press Enter. The field now reads **status is failing and (name contains api or url contains health)**. The new filter is grouped with the filter right before it. The other joins don't change. Typing `and` works the same way. Without a typed join, a new filter joins with **and**. Press Backspace in the empty field to remove a typed join.

## Group filters

A group holds filters joined by its own **and** or **or**. Click the word inside a group to switch it.

To build a group from the keyboard, type `(` in the filter field. An empty group opens with the cursor inside it. The filters you add next go into it. Type `or` before a filter to join the group's filters with **or**. Type `)` to close the group and go back to the top level. Leaving the field or pressing Escape also closes it.

For example, to find checks with "checkout" in their name or in their URL:

1. Type `(`.
2. Type `name` and press Enter. Type `checkout` and press Enter.
3. Type `or url` and press Enter. Type `checkout` and press Enter.
4. Type `)`.

The field then holds **(name contains checkout or url contains checkout)**.

With the mouse:

- **Make a group:** drop a filter onto another one.
- **Move filters:** drag a filter to reorder it, or to move it into or out of a group.
- **Move a group:** drag it by its handle.

A group can't hold another group.

More examples:

- On Heartbeats, **status is failing and (period > 1h or availability < 99.9)** finds failing heartbeats that either expect a ping less often than hourly or are below 99.9% available.
- On Monitors, **status is failing or tags is critical** lists every failing check and every check tagged `critical`.

## Group the rows

On Reporting, you can group the rows by location. Type `group by location` or `groupBy:location` in the filter field and press Enter. A **group by Location** block shows in the field. The table then lists one row for each check and location. A **Location** column shows before **Success**.

The block isn't a filter. It doesn't join filters with **and** or **or**. It can't go into a group. Drag it, or press Alt+Left or Alt+Right on it, to move it anywhere in the field. Remove it to list one row per check again.

## Use the keyboard

Every part of a filter is reachable from the keyboard.

| Key | What it does |
|-----|--------------|
| Tab, Shift+Tab, Left, Right | Moves between the parts of the filters and the joining words |
| Typing on a value | Changes the value, or searches the picker of a field with many values |
| Enter, Space | Opens the picker of the focused part, or switches the focused joining word |
| Backspace, Delete | Removes the focused filter, or a filter whose value you are typing while it is empty |
| Alt+Left, Alt+Right | Moves the focused filter left or right. It can move into and out of groups. |

In the empty filter field, Backspace removes a typed join first, then the last filter.

## Save and share filters

The page URL holds every filter and its groups. Copy it to send the same list to a teammate. On Monitors, Heartbeats, Test sessions and Reporting, you can save filters you use often as a [view](/platform/views).
