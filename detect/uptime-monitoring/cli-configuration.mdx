The Checkly CLI enables you to define, version control, and deploy uptime monitors as code. This approach provides better maintainability, team collaboration, and integration with your development workflow.

## Getting Started with CLI

### Installation

Install the Checkly CLI in your project:

```bash
npm install --save-dev checkly
```

### Project Setup

Initialize a new Checkly project:

```bash
npx checkly init
```

This creates the basic project structure with configuration files and example monitors.

## URL Monitor Configuration

### Basic URL Monitor

<CodeGroup dropdown>

```ts url-monitor.check.ts
import { UrlMonitor, UrlAssertionBuilder } from 'checkly/constructs'

new UrlMonitor('homepage-check', {
  name: 'Homepage Availability',
  activated: true,
  locations: ['us-east-1', 'eu-west-1', 'ap-southeast-1'],
  frequency: 5, // minutes
  maxResponseTime: 2000, // ms
  request: {
    url: 'https://www.myapp.com',
    assertions: [
      UrlAssertionBuilder.statusCode().equals(200),
    ]
  },
  tags: ['production', 'frontend', 'critical']
})
```

### Advanced URL Monitor with Response Time Limits

URL monitors only assert on the HTTP status code. If you need to send custom headers or assert on the response body, use an [API check](/detect/synthetic-monitoring/api-checks/overview) instead.

The samples on this page define their alert channels inline to stay self-contained. In a real project, define each [alert channel](/constructs/alert-channel) once in a shared file, export it, and import it where needed; a logical ID may only be used once per project.

<CodeGroup dropdown>

```ts api-monitor.check.ts
import { UrlMonitor, UrlAssertionBuilder, EmailAlertChannel, SlackAppAlertChannel } from 'checkly/constructs'

const emailAlerts = new EmailAlertChannel('email-alerts', {
  address: 'ops@myapp.com'
})
const slackAlerts = new SlackAppAlertChannel('slack-alerts', {
  slackChannels: ['#alerts']
})

new UrlMonitor('api-health-check', {
  name: 'API Health Check',
  activated: true,
  locations: ['us-east-1', 'eu-west-1'],
  frequency: 2, // minutes
  degradedResponseTime: 500, // ms
  maxResponseTime: 1000, // ms
  request: {
    url: 'https://api.myapp.com/health',
    assertions: [
      UrlAssertionBuilder.statusCode().equals(200),
    ]
  },
  alertChannels: [emailAlerts, slackAlerts],
  tags: ['production', 'api', 'critical']
})
```


## Shared Configuration and Groups

### Monitor Groups

Organize related monitors using groups:

<CodeGroup dropdown>

```ts api-monitoring-group.check.ts
import { CheckGroupV2, UrlMonitor, EmailAlertChannel, SlackAppAlertChannel } from 'checkly/constructs'

const emailAlerts = new EmailAlertChannel('email-alerts', {
  address: 'ops@myapp.com'
})
const slackApiAlerts = new SlackAppAlertChannel('slack-api-alerts', {
  slackChannels: ['#api-alerts']
})

const apiGroup = new CheckGroupV2('api-monitoring', {
  name: 'API Monitoring',
  activated: true,
  locations: ['us-east-1', 'eu-west-1', 'ap-southeast-1'],
  frequency: 5,
  alertChannels: [emailAlerts, slackApiAlerts],
  tags: ['api', 'production']
})

// Monitors inherit group settings
new UrlMonitor('users-api', {
  name: 'Users API',
  group: apiGroup,
  request: {
    url: 'https://api.myapp.com/users'
  }
})

new UrlMonitor('orders-api', {
  name: 'Orders API',
  group: apiGroup,
  request: {
    url: 'https://api.myapp.com/orders'
  }
})
```

### Environment Variables

Use environment variables to vary the configuration per environment:

<CodeGroup dropdown>

```ts environment-config.check.ts
import { UrlMonitor, UrlAssertionBuilder } from 'checkly/constructs'

// Environment-specific configuration
const baseUrl = process.env.BASE_URL || 'https://api.myapp.com'
const environment = process.env.ENVIRONMENT || 'production'

new UrlMonitor(`${environment}-api-check`, {
  name: `${environment.toUpperCase()} API Health`,
  activated: environment === 'production',
  locations: environment === 'production'
    ? ['us-east-1', 'eu-west-1', 'ap-southeast-1']
    : ['us-east-1'],
  frequency: environment === 'production' ? 2 : 10,
  maxResponseTime: environment === 'production' ? 2000 : 5000, // ms
  request: {
    url: `${baseUrl}/health`,
    assertions: [
      UrlAssertionBuilder.statusCode().equals(200),
    ]
  },
  tags: [environment, 'api', 'health']
})
```

## Deployment and CI/CD Integration

### Deploying Monitors

Deploy your monitors to Checkly:

```bash
# Deploy all monitors
npx checkly deploy

# Deploy with environment variables
ENVIRONMENT=production BASE_URL=https://api.myapp.com npx checkly deploy

# Test before deploying
npx checkly test

# Preview changes
npx checkly deploy --preview
```

### GitHub Actions Integration

Example GitHub Actions workflow:

```yaml .github/workflows/checkly.yml
name: Deploy Checkly Monitors

on:
  push:
    branches: [main]
    paths: ['monitoring/**']

jobs:
  deploy-monitoring:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '22'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Test monitors
        run: npx checkly test
        env:
          CHECKLY_API_KEY: ${{ secrets.CHECKLY_API_KEY }}
          CHECKLY_ACCOUNT_ID: ${{ vars.CHECKLY_ACCOUNT_ID }}

      - name: Deploy monitors
        run: npx checkly deploy
        env:
          CHECKLY_API_KEY: ${{ secrets.CHECKLY_API_KEY }}
          CHECKLY_ACCOUNT_ID: ${{ vars.CHECKLY_ACCOUNT_ID }}
          ENVIRONMENT: production
          BASE_URL: https://api.myapp.com
```

## Advanced Patterns

### Dynamic Monitor Generation

Generate monitors programmatically:

<CodeGroup dropdown>

```ts dynamic-monitors.check.ts
import { UrlMonitor, UrlAssertionBuilder } from 'checkly/constructs'

// Monitor multiple API endpoints
const endpoints = [
  { path: '/users', name: 'Users API' },
  { path: '/orders', name: 'Orders API' },
  { path: '/products', name: 'Products API' },
  { path: '/payments', name: 'Payments API' }
]

endpoints.forEach((endpoint, index) => {
  new UrlMonitor(`api-${endpoint.path.replace('/', '')}-check`, {
    name: endpoint.name,
    activated: true,
    locations: ['us-east-1', 'eu-west-1'],
    frequency: endpoint.path === '/payments' ? 1 : 5, // More frequent for critical endpoints
    maxResponseTime: endpoint.path === '/payments' ? 500 : 1000, // Stricter limit for critical endpoints
    request: {
      url: `https://api.myapp.com${endpoint.path}`,
      assertions: [
        UrlAssertionBuilder.statusCode().equals(200),
      ]
    },
    tags: ['api', 'production', endpoint.path.replace('/', '')]
  })
})
```

### Version Control
- **Commit monitor changes** with descriptive messages
- **Use branch protection** for production monitor deployments
- **Review monitor changes** before merging to main branch
- **Tag releases** for monitor configuration versions

### Testing and Validation
- **Test monitors locally** before deployment
- **Use preview deployments** to validate changes
- **Monitor the monitors** - track deployment success
- **Rollback capabilities** for failed deployments
