The Usage API reports contract usage for the organization associated with the account in your request. Use it to inspect contract terms, track consumed credits, and export usage data to your own reporting systems.

<Accordion title="Before you begin">
  You need a user or service API key and the ID of an account in the organization. Send the key in the `Authorization: Bearer <api-key>` header and the account ID in the `X-Checkly-Account` header. Your key must have the **Owner** or **Admin** role for that account. Legacy account API keys are not supported. See [Using the Checkly API](../overview) for authentication details.
</Accordion>

## Choose an endpoint

| Endpoint | Use it to |
| --- | --- |
| [`GET /v1/usage/terms`](./get-usage-terms) | Resolve the applicable usage terms and list every account in the organization. |
| [`GET /v1/usage/summary`](./get-usage-summary) | Return totals and projections for an inclusive date range. |
| [`GET /v1/usage/series`](./get-usage-series) | Return paginated usage rows grouped by time, account, check type, or both dimensions. |

## Resolve usage terms and dates

Each request resolves one set of usage terms for the organization:

- Pass `usageTermsId` to select a specific contract.
- Otherwise, pass `to` to select the contract active on that date.
- If you omit both values, `to` defaults to today.

Dates use `YYYY-MM-DD` and are inclusive. For summary and series requests, `from` defaults to the contract's `usageStartDate`. When a requested range extends beyond the available usage window, the API clamps it to `usageStartDate` and `contractEndDate`. Series responses then include a `PARTIAL_WINDOW` warning.

## Filter and group usage

Summary and series requests accept `accountIds` and `checkTypes`. Repeat a parameter or provide comma-separated values. If you omit `accountIds`, the response covers every account in the resolved usage terms.

The series endpoint also supports:

- `interval`: `day` (default), `week`, `month`, or `total`. Weekly buckets start on Monday. Monthly buckets follow calendar months.
- `groupBy`: `account`, `checkType`, or `account,checkType` (default).
- `limit`: 1–500 rows per page; the default is 100.
- `nextId`: the opaque cursor from the previous response.

Rows are ordered by period, account ID, and check type. The API returns zero-valued rows for requested time and grouping combinations that have no usage, which keeps exported series structurally consistent.

## Interpret metrics and credits

Every `totals` or series row contains `credits` and a `CHECK_RUN` meter. Its `measures` object includes run outcomes, billable units, Multistep request counts, and Playwright billable duration in milliseconds.

`credits.used` is calculated from standard and premium billable units using the rates in the resolved usage terms.

Summary projections compare four windows: usage since `usageStartDate`, the last 30 days, the last 7 days, and the last day. Each window reports annualized budget percentage and, where meaningful, projected contract-end consumption and estimated weeks until the budget is exhausted.

## Paginate a series

Send a non-null `nextId` unchanged with the same query parameters to retrieve the next page. Changing a parameter invalidates the cursor.

## Handle errors

The API returns `400` for invalid requests, `401` or `403` for authentication and permission errors, and `404` when no matching usage terms are found.
